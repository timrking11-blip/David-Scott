## Data-sharing assessment (read paths)

Seat constraint. Brad has one reported seat and Sage is not installed on his computer [E-SAGE-038]. Sage ties a single-user licence to one individual and extra workstations to their own licences [E-SAGE-012], and whether an SDK or ODBC read counts as a user is not stated [E-SAGE-011]. Every automated Sage read below therefore carries a seat question and may need a time window when staff are out of Sage [E-SAGE-048]. Several operations take exclusive locks on the company files and can block a read [E-SAGE-007].

Sage ODBC or OLE DB read.
- Refresh: no source describes a change feed or incremental read, so the dashboard pulls on a schedule, full or date-filtered, and stores each pull as a time-stamped snapshot [E-SAGE-047]. Reads are read-only, 32-bit and need a data-access password [E-SAGE-021]. Refresh time is untested; the PoC times it [E-SAGE-021].
- Reconciliation: compare record counts and totals in the snapshot with a Sage report that a person runs [E-SAGE-047].
- Failure recovery: if a pull fails (locked company, changed password, release conversion, offline host), keep the last good snapshot, show its age, and pull again after the cause is cleared [E-SAGE-047; E-SAGE-007; E-SAGE-020]. Sage support will not help with third-party ODBC tools, so the owner of the dashboard carries the support burden [E-SAGE-021].

Sage CSV export.
- Refresh: run by a person from the Sage menus; scheduled export was not checked [E-SAGE-023]. Cadence is therefore as often as someone runs it.
- Reconciliation: check row counts and totals against a Sage report, and use the exact template layout so field order does not drift [E-SAGE-024; E-SAGE-047].
- Failure recovery: if no one runs the export, the dashboard shows the age of the last file; a missed export is repaired by running it and loading the newer file [E-SAGE-047; E-SAGE-023].

Sage SDK read.
- Refresh: same scheduled-pull pattern. The SDK client needs a one-time approval inside Sage 50, accesses one company at a time, and has no security model once approved [E-SAGE-005; E-SAGE-006; E-SAGE-047].
- Reconciliation: counts and totals against a Sage report [E-SAGE-047].
- Failure recovery: a Pending or locked result, an exclusive lock, or an SDK build that trails the installed release stops the read; keep the last snapshot and retry after the cause is cleared [E-SAGE-006; E-SAGE-007; E-SAGE-019; E-SAGE-047]. Seat use and fees are open [E-SAGE-010; E-SAGE-011].

Shipping status and tracking read (portal, Unishippers API or ShipStation).
- Refresh: the dashboard polls on a schedule; a ShipStation connection retrieves tracking but has no webhook tracking [E-SHIP-012; E-SHIP-036]. Through the portal a person reads status [E-SHIP-006].
- Reconciliation: match tracking numbers with the Unishippers combined invoice [E-SHIP-006; E-SHIP-020] and with what staff entered in Sage [E-SAGE-042]. Where the number lives in Sage is open [E-SAGE-025].
- Failure recovery: keep the last known status, show its age, and fall back to the portal for a manual check [E-SHIP-036; E-SHIP-006]. If an account migration changes access, the read stops until the new platform is set up [E-SHIP-008; E-SHIP-034].

Email read (Microsoft 365 or Google Workspace, platform unconfirmed).

- Reconciliation: compare messages seen with messages processed [E-MAIL-014].
- Failure recovery: also list the mailbox on a schedule as a safety net, and after an outage reprocess everything received since the last good run [E-MAIL-014]. Email content is data, never instructions [E-AI-026].

WooCommerce partial product reference read (optional). Sage holds all products, newly introduced and standard, and is the product master; the website carries some but not all [E-SAGE-054; E-ECOM-014].
